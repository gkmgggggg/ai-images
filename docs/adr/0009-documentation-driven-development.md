# ADR-0009 采用文档驱动开发

## 背景

第一阶段按一份需求与架构文档开发完成，但文档与代码没有约束关系：实现过程中的变化（如 Vite 版本、比例标签）只能靠人工回写。后续开发会大量借助 AI 助手，需要一份它能读懂、且与代码保持一致的依据。

## 决定

- 文档放在仓库 `docs/`，与代码一起评审和提交；在线文档不再作为依据。
- 功能变更先写规格，架构决策写 ADR；需求编号是规格、代码、测试之间的纽带。
- 接口文档与需求追溯矩阵由代码生成，`scripts/docs.py check` 在本地与 CI 中检查文档是否过期、链接是否有效、已实现需求是否有测试。
- `CLAUDE.md` 规定 AI 助手遵循同一流程。

流程细节见 [文档驱动开发流程](../process/doc-driven-development.md)。

## 后果

- 每个功能变更多了写规格的成本；小改动可以豁免，由分级规则控制。
- 文档过期会让检查失败，迫使在同一次提交中更新文档。
- 检查只能发现「结构性」脱节（缺测试、生成文件过期、坏链接），文字描述是否准确仍依赖评审。
