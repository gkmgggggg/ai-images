# ADR-0005 重新导入时保护管理员的手工修改

## 背景

上游会持续更新，需要重复导入（F08）；管理员也会在后台修正标题、提示词、图片（F10）。如果导入无条件覆盖，手工修改会丢失；如果导入跳过所有已存在的案例，上游的修正又进不来。

## 决定

在案例上记录 `overridden_fields`：后台修改上游案例的某个上游字段（含 `images`、`tags`）且值确有变化时，把字段名加入列表；导入时逐字段跳过列表中的字段，其余字段照常更新。编辑页提供「恢复上游同步」清空列表。发布状态不受导入影响，也不记入列表。

## 备选方案

| 方案 | 为什么没选 |
| --- | --- |
| 导入总是覆盖 | 手工修改丢失 |
| 案例被改过就整条跳过 | 上游对其他字段的修正也进不来 |
| 保存每个字段的上游版本并做三方合并 | 实现复杂，当前规模不需要 |

## 后果

- 管理员能看到哪些字段不再跟随上游（后台列表与编辑页都有提示）。
- 已被保护的字段如果上游也改了，不会有提醒；需要时管理员可恢复同步后重新导入。
- 前端只提交表单中实际改动过的字段，避免未改动的字段被误标记。
