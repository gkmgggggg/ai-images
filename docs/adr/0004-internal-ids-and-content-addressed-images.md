# ADR-0004 内部自增 ID 与上游编号解耦，图片按内容 hash 命名

## 背景

上游「例 N」的编号跨分类重复：668 条案例只有 397 个不同编号。原站用编号作为图片文件名（`case-NNN.jpg`），上游一旦出现同编号且都有图的情况，图片会互相覆盖。此外后台需要创建不来自上游的案例。

## 决定

- 案例使用数据库自增主键；上游编号只作为 `(category_id, upstream_no)` 联合唯一键，用于导入时定位。手工案例的 `upstream_no` 为空。
- 图片以文件内容的 sha256 命名，衍生图名为 `<sha>-<尺寸>.webp`；同一内容只存一份，删除时检查引用计数。

## 后果

- 不会再发生图片覆盖；图片 URL 内容不变即地址不变，可以设置一年的不可变缓存。
- 案例 id 与上游编号不同，排查问题时需要通过后台或数据库对照（后台列表显示「上游 例N」）。
- 分类改名不影响定位，因为按分类 id 而非名称。
- **已知问题**：导入按「当前分类 id + 上游编号」定位案例。管理员把上游案例改到其他分类后，下次导入在原分类找不到它，会重复创建一条。修复方案见 [规格 0001](../specs/0001-stable-upstream-identity.md)（待批准）。
